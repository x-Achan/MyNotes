### 核心问题诊断

**问题1: 严重过拟合 — train loss持续下降但val loss飙升**

- train loss: 12.89 → 2.65 (下降79%), val loss: 56.32 → 106.11 (上升88%)
- mAP在epoch 6达到峰值0.0953后持续下降，典型过拟合曲线
- loss_ce从0.304降到0.004(接近零)，说明模型在训练集上几乎完美分类，但泛化极差
- **根因**: backbone容量不足(7.44M)，特征判别性不够，检测头开始记忆训练样本; weight_decay=0.0001远低于DINO标准0.001; 数据增强太弱(无随机裁剪/尺度抖动/Mosaic)

**问题2: 时序建模严重不足 — 最关键问题**

- VideoMamba的时序扫描(temporal_first)将同一空间位置跨8帧排列，但SSM的hidden state容量有限(192-dim), 8帧×2720 tokens=21760个token的信息流经单一序列方向, 时序关联被稀释
- Temporal Fusion仅在SFP之后、DINO之前做浅层融合(SE-gated conv1d), 0.06M参数, 几乎无力建模复杂时序依赖
- SFP对每帧独立处理, 时序信息无法指导多尺度特征构建
- **整条链路中, 时序信息只在backbone内部(Mamba SSM)和最后一步TemporalFusion出现, 中间的Feature Aggregator和SFP完全无视时序**
- mAP_large从0.0853波动到0.1740不稳定, 说明大目标的时序一致性建模失败

**问题3: Single-scale backbone + SFP 伪多尺度**

- out_indices 4层输出空间分辨率完全相同(1/16 stride)
- Feature Aggregator仅做加权求和, 本质还是单尺度
- SFP通过deconv/strided conv人工构造4尺度, 缺乏真正的多尺度感受野
- 对UAV小目标检测尤其不利 — mAP_small=0.1123, 远低于mAP_medium=0.1445

**问题4: num_queries配置矛盾**

- yaml中 `num_queries: 100` 但 `two_stage_type: standard` 使用Top-K=300 proposals
- 100个query可能不足以覆盖UAVDT场景中密集的小目标车辆

**问题5: 数据增强太弱 & 正则化不足**

- 缺失: 随机裁剪、尺度抖动、Mosaic、多尺度训练
- weight_decay=0.0001偏低(DINO标准0.001)
- drop_path_rate=0.1偏低(24层Mamba, 标准ViT用0.1-0.3按深度线性增长)

## 三、时序策略创新方向 (核心研究路线)

> **核心定位**: 以VideoMamba的SSM时序扫描机制为切入点, 在时序建模策略上做系统性创新, 而非单纯换backbone或堆参数。

### 方向1: 运动引导的时序选择性扫描 (Motion-Guided Temporal Selective Scan) — 核心创新

**动机**: 当前temporal_first扫描将8帧所有token按固定顺序排列, SSM被动接收。但UAV视频中, 运动目标只占少数token, 大量背景token浪费了SSM的hidden state容量。192-dim的SSM hidden state要编码21760个token的信息, 信噪比极低。

**核心思想**: 利用帧间差异估计运动显著性, 重排Mamba的扫描路径 — 运动区域优先扫描、高信息量token获得更多SSM hidden state容量, 背景token可跳过或压缩。

**具体方案: 运动显著性引导扫描重排 (Motion-Salience Guided Scan Reordering)**

```
输入: [B, N*T, C] — temporal_first排列的token序列

1. 计算帧间运动显著性图:
   frame_diff = |x[t+1] - x[t]|  对每对相邻帧
   motion_score = gap(feat) → Linear → Sigmoid  # 轻量网络预测运动分数

2. 按运动分数重排序列:
   高运动token → 序列前部(先被SSM处理, 获得更多hidden state容量)
   低运动token → 序列后部(后处理, SSM已有足够的上下文)

3. Mamba SSM 按新序列顺序扫描

4. 输出后恢复原始空间顺序 (用于后续模块)
```

**实现要点**:
- 重排操作: `torch.gather` 按排序索引重排, 可微分
- 轻量运动估计: 1层Linear+GELU+Linear, 参数量<0.01M
- 训练初期随机重排(学习率warmup), 逐渐过渡到运动引导
- 可在每6-8层Mamba block后做一次重排, 适应不同语义深度

**参考论文**:
- **VMamba** (Liu et al., 2024) — Cross-Scan Module, 4方向空间扫描
- **QuadMamba** (Xie et al., 2024) — 可学习的quadtree-based选择性扫描
- **EventMamba** (Ge et al., AAAI 2025) — 一致性遍历序列化
- **RVMamba** (Chen et al., 2025) — 学习型扫描策略, 用权重调制选择性更新跨帧hidden state

**预期收益**: 高 — SSM的hidden state是稀缺资源, 让运动目标token优先获取容量, 直接提升时序特征质量

---

### 方向2: 分层时序建模 (Hierarchical Temporal Modeling) — 方向1的增强

**动机**: 当前整个backbone是24层flat的Mamba, 时序信息在一维序列中一次性处理。不同语义层次需要不同粒度的时序建模 — 浅层需要短时精细运动, 深层需要长时语义关联。

**核心思想**: 在Mamba的不同深度阶段使用不同的时序策略, 构建层次化时序表征。

**具体方案: 3阶段分层时序扫描**

```
VideoMamba 24层 → 3个阶段:

阶段1 (Layer 0-7): 短时精细扫描
  - 只对中心帧±1的3帧做temporal_first扫描
  - 目的: 捕获帧间微小运动(小目标位移)
  - 序列长度: N*3 ≈ 8160 (而非N*8=21760)

阶段2 (Layer 8-15): 中时双向扫描
  - 对5帧(中心±2)做temporal_first双向扫描
  - 引入运动引导的重排(方向1)

阶段3 (Layer 16-23): 全帧全局扫描
  - 对8帧做完整temporal_first扫描
  - 使用运动引导重排 + temporal compression

每阶段之间: 时序池化/压缩模块
  - 将前阶段的时序特征压缩为少量anchor token
  - anchor token参与下一阶段的SSM扫描, 携带历史时序信息
```

**实现要点**:
- 需修改 `VisionMamba.forward_features()` 的扫描逻辑
- 每阶段内部保持原有BiMamba结构, 只改输入序列的构造方式
- 阶段间的时序压缩: 对T帧特征做temporal attention或conv1d压缩到T/2帧
- anchor token: 类似HieraMamba, 在多时间粒度上产生紧凑token

**参考论文**:
- **ABMamba** (Yashima et al., 2026) — 对齐的层级双向扫描
- **HieraMamba** (An & Grauman, 2025) — Anchor-MambaPooling块
- **Backtrace Mamba** (Yan et al., AAAI 2026) — 层级记忆机制

**预期收益**: 高 — 大幅减少单次SSM扫描的序列长度(N*3 vs N*8), 提升SSM hidden state利用率, 同时构建多粒度时序特征

---

### 方向3: 运动引导的时序特征聚合 (Motion-Guided Temporal Aggregation) — 替换现有TemporalFusion

**动机**: 当前TemporalRecalibFusion在SFP之后做, 且只用中心帧均值和时序方差做gating, 没有显式的运动建模。UAV场景中相机运动和目标运动交织, 简单的时间卷积无法区分。0.06M参数/4组的Temporal Fusion是整条链路中最薄弱的环节。

**核心思想**: 用运动信息(帧间差异)显式引导时序特征的聚合方式, 在SFP之前先做时序融合, 让多尺度特征本身就包含时序上下文。

**具体方案: 运动引导时序对齐融合 (Motion-Guided Temporal Alignment Fusion)**

```
替换位置: 在Feature Aggregator之后、SFP之前 (提前融合)

输入: [B*T, N, C] — 多帧特征

1. 计算帧间运动图:
   center_feat = x[T//2]  # [B, N, C]
   motion_map = Σ|x[t] - center_feat| / (T-1)  # [B, N, C] 帧间平均差异

2. 运动显著性权重:
   motion_score = conv1d(motion_map.mean(-1)) → sigmoid  # [B, N] 每个空间位置的运动分数

3. 运动引导聚合:
   # 高运动区域: 使用可变形对齐聚合邻帧信息
   # 低运动区域: 保留中心帧特征 (避免相机运动引入噪声)
   aligned_feats = deformable_temporal_align(x)  # 沿时间轴的可变形对齐
   fused = motion_score * aligned_feats + (1-motion_score) * center_feat

4. 时空交互增强:
   # 在融合后做轻量时空注意力 (而非简单的conv1d)
   fused = temporal_attention(fused, center_feat)  # 中心帧query, 邻帧key/value

输出: [B, N, C] — 单帧时序融合特征
```

**关键改进点**:
- **时序融合位置前移**: SFP之前融合, 让多尺度特征包含时序信息
- **运动显式建模**: 用帧间差异而非方差, 更精准地捕获目标运动
- **可变形时序对齐**: 替代固定kernel的conv1d, 沿时间轴自适应对齐
- **参数量增加**: 从0.06M提升到~0.3M, 仍远小于transformer的11.89M

**参考论文**:
- **FGFA** (Zhu et al., ICCV 2017) — 光流引导特征聚合
- **TransVOD Lite** (Deng et al., AAAI 2023) — 时序可变形注意力模块
- **FAQ** (Cui & Yang, 2023) — Feature Aggregated Queries
- **MOCID** (Zhang et al., AAAI 2025) — 运动上下文和位移信息学习

**预期收益**: 高 — 直接解决时序融合太弱的问题, 同时运动建模对UAV场景有强针对性

### 方向4: 双向时序解耦扫描 (Decomposed Bidirectional Temporal Scan) — 改进BiMamba

**动机**: 当前bidirectional Mamba只是正反两个方向各扫一次, 前向和后向共享同一套参数。但视频中的时序因果关系是不对称的 — 前向关注"过去→现在"的预测, 后向关注"未来→现在"的回溯, 两者应建模不同的时序模式。

**核心思想**: 将双向SSM的forward和backward路径解耦, 赋予独立参数和不同的时序归纳偏置。

**具体方案:**

```
当前BiMamba:
  y_forward = SSM(x, direction=forward)   # 共享参数
  y_backward = SSM(x_reverse, direction=backward)  # 共享参数
  y = y_forward + y_backward

解耦BiMamba:
  y_forward = SSM_causal(x)        # 因果方向: 只看过去帧
  y_backward = SSM_anticausal(x_reverse)  # 反因果方向: 只看未来帧
  # 各自独立参数 (in_proj, x_proj, dt_proj, A, B, C)
  # 前向偏置: 学习运动起始特征
  # 后向偏置: 学习运动终止特征/纠正前向误判

  # 交叉交互 (而非简单相加)
  y_interact = lightweight_cross_attn(y_forward, y_backward)
  y = y_interact
```

**实现要点**:
- 修改 `mamba_ssm` 的BiMamba实现, 将forward/backward的in_proj和dt_proj分离
- 轻量交叉注意力: 1层Linear Attention, 参数增量<0.05M/layer
- 可只在深层(Layer 16-23)使用解耦扫描, 浅层保持共享参数节省计算

**参考论文**:
- **Video Mamba Suite / DBM** (Chen et al., IJCV 2024) — Decomposed Bidirectional Mamba block
- **Separated Bidirectional Mamba** (Liu & Peng, 2025) — 从状态转换视角理解帧变化
- **BiTPerceiver** (Wang et al., ITSC 2025) — forward-then-backward时序依赖建模

**预期收益**: 中 — 改进SSM内部的双向信息流, 对时序一致性有帮助

### 方向5: 时序Query传播 (Temporal Query Propagation for DINO) — 改进检测头

**动机**: 当前DINO的100个query每帧独立初始化(two-stage proposals), 没有利用前一帧的检测结果。视频检测中, 目标位置在帧间高度连续, query应该沿时间传播。

**核心思想**: 将相邻帧的检测结果(boxes + embeddings)作为先验传播到中心帧的query初始化中。

**具体方案:**

```
当前: center_frame → Encoder → Top-K proposals → Decoder → predictions

改进:
  1. 邻帧辅助检测:
     对每帧独立跑Encoder, 得到每帧的encoder proposals

  2. 时序Query初始化:
     center_proposals = encoder_proposals[T//2]  # 中心帧proposals
     neighbor_proposals = encoder_proposals[T//2±1]  # 邻帧proposals

     # 邻帧proposals的运动补偿偏移
     motion_offset = lightweight_motion_net(center_feat, neighbor_feat)
     shifted_neighbor = neighbor_proposals + motion_offset

     # 合并: center_proposals + top-shifted_neighbor → 增强的query

  3. Cross-frame Query Attention:
     # 当前帧query与邻帧encoder memory做cross-attention
     q = center_queries
     k,v = concat(center_memory, neighbor_memory)
     enhanced_q = cross_attn(q, k, v)
```

**实现要点**:
- 需要修改 `DeformableTransformer.forward()`, 在encoder后增加跨帧attention
- motion_offset网络: 2层MLP, 输入为center和neighbor的proposal坐标差
- 推理时不增加计算量(只用中心帧), 训练时增加约10%计算量

**参考论文**:
- **TransVOD** (Deng et al., CVPR 2022) — 端到端transformer视频检测
- **StreamVOD** (Yu et al., AAAI 2024) — 流式增量时序检测
- **FAQ** (Cui & Yang, 2023) — Feature Aggregated Queries

**预期收益**: 中高 — 提升目标检测的时序一致性, 对被遮挡目标的恢复特别有效

## 四、推荐实施方案 (分阶段)

### 阶段1: 训练策略修复 (1-2天, 预期mAP: 0.095 → 0.15+)

不改架构, 只修训练配置, 快速验证baseline是否提升:

1. **num_queries: 100 → 300** (yaml配置修改)
2. **weight_decay: 0.0001 → 0.001** (抑制过拟合)
3. **drop_path_rate: 0.1 → 0.2** (增强正则化)
4. **添加数据增强**: RandomCrop、ScaleJitter (在 `_transform_clip()` 中)
5. **eval_interval: 6 → 2** (更频繁评估, 找到最佳epoch)
6. **backbone_lr_multiplier: 0.25 → 0.1** (进一步减缓backbone学习)

### 阶段2: 时序融合强化 (3-5天, 预期mAP: 0.15 → 0.20+)

实现**方向3: 运动引导时序特征聚合**, 替换当前薄弱的TemporalFusion:

1. 实现 `MotionGuidedTemporalFusion` 类
2. 将时序融合位置从SFP之后移到SFP之前
3. 添加帧间运动显著性计算和运动引导gating
4. 训练验证, 对比recalib基线

### 阶段3: 时序选择性扫描 (5-7天, 预期mAP: 0.20 → 0.25+)

实现**方向1: 运动引导的时序选择性扫描**, 修改backbone内部扫描策略:

1. 实现运动显著性估计网络
2. 实现基于运动分数的序列重排逻辑
3. 修改 `VisionMamba.forward_features()` 支持动态扫描路径
4. 与阶段2的结果对比消融

### 阶段4: 分层时序建模 (可选, 7-10天)

实现**方向2: 分层时序建模**, 在方向1的基础上构建3阶段扫描:

1. 修改VideoMamba为3阶段, 每阶段不同帧窗口
2. 实现阶段间时序压缩模块
3. 与阶段3结果对比消融

## 五、创新方向优先级与可行性评估

| 方向 | 创新性 | 实现难度 | 对mAP预期收益 | 论文叙事价值 | 推荐优先级 |
|------|--------|----------|---------------|-------------|-----------|
| **方向1: 时序选择性扫描** | ★★★★★ | 中 | 高 | 极高 — 可做核心贡献 | ★★★★★ |
| **方向3: 运动引导时序聚合** | ★★★★ | 中 | 高 | 高 — 结合UAV场景特色 | ★★★★ |
| **方向2: 分层时序建模** | ★★★★ | 中高 | 高 | 高 — 系统性创新 | ★★★ |
| **方向4: 双向时序解耦扫描** | ★★★ | 低 | 中 | 中 — 改进现有bimamba | ★★ |
| **方向5: 时序Query传播** | ★★★ | 中 | 中高 | 中 — DETR社区已有探索 | ★★ |

### 推荐组合策略

**主线**: 方向1(时序选择性扫描) + 方向3(运动引导时序聚合)
- 方向1解决"SSM如何更有效地扫描时序"的根本问题
- 方向3解决"时序特征如何被检测头有效利用"的落地问题
- 两者互补: 前者改backbone内部扫描, 后者改backbone→head之间的融合

**辅线**: 方向2(分层时序建模) — 作为方向1的增强
- 在不同Mamba层深度使用不同的选择性扫描策略, 形成"浅层短时精细扫描 + 深层长时语义扫描"的层次

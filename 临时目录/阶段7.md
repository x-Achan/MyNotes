三、论文调研后的判断
- RVM，CVPR 2026证明递归状态和预测式自监督有价值，但它是大规模表示预训练方法，不是即插即用检测模块。本项目已经试过正确二维 ConvGRU，真实历史收益不足，因此 RVM 只能作为后期“对象 token 预测辅助”，不能再作为主线。
- TA-GRU与本项目结果高度一致：其 VisDrone 消融中，朴素 ConvGRU 从 18.71 降到 16.55；加入 DeformAlign 后才到 20.03，再加注意力与融合才获得主要收益。它说明真正有效的是目标选择、对齐和抑制背景，而不是 GRU 本身。
- YOLOV，AAAI 2023和YOLOV++是最适合当前工程的母版：先从一阶段检测头压缩前景候选，再做候选级关系聚合。YOLOV++ 还指出，稀疏候选不适合直接照搬原密集标签分配，分类分数与 IoU 质量应分别优化。
- FAIM，WACV 2025进一步证明，proposal 中的背景污染会破坏聚合。VisDrone 没有实例掩码，因此不应直接复制 mask 分支，但应采用更小的对象区域特征与前景门控。
- Temporal RoI Align支持让当前候选主动从参考特征图局部读取支持，而不是整图 warp。这正适合修复当前 IoU 0.3～0.5 的候选。
- MEGA和SELSA说明近邻帧主要贡献定位，较远帧主要贡献语义，不应全部塞入同一个融合模块。
- 最新的 D2FANet，CVPR 2026引入频域时序聚合，值得作为后续研究，但其密集双域结构复杂、归因困难，不适合作为当前成功概率最高的第一步。
四、推荐架构
每帧共享 YOLOv10s
        │
        ├─ one2one + one2many raw candidates
        │
        ▼
空间多样性选择 / NMS 去重 / P3-P4 动态配额
        │
        ▼
中心候选 query ─────── 参考帧候选 key/value
        │                        │
        └──── 外观 + 类别 + 质量 + 近程几何 ────┐
                                               ▼
                                  稀疏 Top-4 软关联
                                  + no-support token
                                               │
                    训练：target_id oracle teacher
                    推理：无 ID student + 蒸馏
                                               │
                         Δclass logit + ΔIoU quality
                         当前框和原分数路径保留
                                               │
                       第一阶段达到正收益后
                                               ▼
                   P3 局部 Temporal RoI box refinement
                   只允许很小、有界的位置残差
核心设计约束：
- target_id 只在训练时建立正关联和 hard negative，推理不需要 ID。
- 同类、空间邻近但不同 ID 的候选必须作为最重要的难负样本。
- 每个参考帧只读取 Top‑2/Top‑4 支持，并加入 no-support token。
- 第一阶段不修改框、不补框，只修正分类 logit 和 IoU-quality。
- 输出残差层严格零初始化；没有可靠支持时逐元素回到单帧 baseline。
- 最终如果仍要求 causal，主模型只使用过去帧；双向 t±4/t±8 只能作为离线上限实验，不能混在 causal 主表中。
五、实际实施路线
Phase A：重做候选验收
不立即训练，先从缓存完成：
- one2one/one2many 候选并集；
- TopK+class-agnostic NMS；
- 按空间网格限制重复候选；
- 动态 P3/P4 配额；
- 统计全 GT、small GT 和“可救援 GT”三种召回。
当前 0.90 all-GT recall@0.5 不应是唯一闸门。建议改为：
- 可救援 GT 的候选召回@0.5 ≥ 0.95；
- 全 GT recall@0.4 ≥ 0.92；
- small recall@0.5 ≥ 0.84；
- 去重后每帧候选最好控制在 384～512。
Phase B：缓存上训练 oracle teacher
冻结 YOLOv10，全程只使用缓存 token：
- 同 ID 为 positive；
- 同类异 ID 为 hard negative；
- 输出 refined class、quality、attention、no-support；
- 先验证 score-only oracle 是否仍能稳定获得 ≥+0.005 mAP50-95。
如果 oracle 在最新缓存上都没有增益，立即停止，不训练 student。
Phase C：可部署 student
Student 输入：
- cls/reg hidden feature；
- raw logits；
- box、尺度层级、相对时间；
- 当前分数与预测质量。
建议初始损失：
L = 1.0 L_assoc
  + 0.5 L_cls_refine
  + 0.5 L_quality
  + 0.5 L_teacher_KD
  + 0.25 L_rank
  + 1.0 L_preserve
先冻结检测器训练 3～5 epoch；通过门槛后只解冻检测头投影层，学习率使用时序模块的 0.1×。
Phase D：受限局部框修正
只处理最佳候选 IoU 位于 0.3～0.5、且关联置信度高的对象：
- 中心候选在参考 P3 上读取 5×5 或 Top‑4 相似位置；
- box delta 限制在约 1～2 个 P3 cell；
- gate 未达到高精度时 box delta 必须为零；
- 仍然禁止从轨迹直接造新框。
Phase E：正式验收
必须同时设置：
- B0：原始 baseline；
- B0‑FT：与时序模型完全相同的额外微调；
- true support；
- current duplicate；
- shuffled same-video；
- cross-video/random；
- reference dropout。
通过条件建议为：
- seed0 val mAP50-95 相对 B0‑FT ≥+0.003；
- true 比 current/random ≥+0.002；
- 三个种子平均 ≥+0.005；
- test 至少比 matched B0‑FT 高 +0.003；若 B0‑FT test 仍约 .166，完整目标应是 ≥.171；
- 额外推理开销不超过约 15%。
最终评估
这项研究目前并不是“没有时序信息”，而是：
时序信息的上限已经被 oracle 证明，但密集融合和部署关联都没有把这个上限可靠转化为 AP。

因此我会暂停所有新的全图 GRU/Mamba 变体，把主力放到 双分支候选去重 → target-ID teacher → 无 ID student → score/quality 重排 → 局部有界框修正。按现有 oracle 上限，比较现实的首轮目标是绝对提升 0.003～0.006 mAP50-95；进一步接近 +0.010 需要同时解决小目标候选定位和关联精度。这个路线比继续堆密集时序模块成功概率明显更高，也最容易形成可信的论文消融链。

# 2.会话技术

会话:
 >用户打开浏览器，访问web服务器的资源，会话建立，直到有一方断开连接，会话结束，一次会话中可以包含多次请求和响应

会话跟踪:
>一种维护浏览器状态的方法，同一个会话的多次请求间共享数据

会话跟踪方案：
- 客户端会话跟踪技术：Cookie
- 服务端会话跟踪技术：Session
- **令牌技术**

Cookie工作流程：
>服务器通过响应头 `Set-Cookie` 将Cookie数据发送给客户端。
> 
>浏览器接收到 `Set-Cookie` 后，会自动将Cookie保存到本地。
> 
>在后续请求中，浏览器会自动携带当前域名下保存的Cookie数据，并通过请求头 `Cookie` 发送给服务器端。

优点：
- http协议中支持的技术

缺点：
- 移动端App无法使用
- 不安全，用户可以自己禁用cookie
- cookie不能跨域（协议/ip/端口必须都一致）

Session工作流程：
> Session基于Cookie实现会话跟踪。服务器创建Session后生成唯一标识JSESSIONID，通过响应头Set-Cookie发送给客户端，浏览器保存该标识，并在后续请求中通过Cookie自动携带JSESSIONID，服务器根据该ID获取对应Session数据。

优点：
- 存储在服务器，安全

缺点：
- 服务器集群环境下无法直接使用Session    
- cookie所有缺点

# 3.Token**令牌技术（主流方案⭐）**

概念：
> Token是一种身份认证凭证。 
> 
> 用户登录成功后，服务器生成Token并返回给客户端， 
> 客户端保存Token，在后续请求中携带Token， 
> 服务器端对Token进行校验，实现用户身份认证。

优点：
- 支持PC、移动端
- 解决集群环境下的认证问题
- 减轻服务器端存储压力

缺点：需要自己编码实现

1. JWT令牌（Json Web Token）

>JWT（JSON Web Token）是一种基于JSON格式， 
>在通信双方之间安全传输信息的令牌技术。


JWT由三部分组成：
- header（头），记录Token令牌的类型、签名算法（例如HS256）
- Payload（有效载荷），携带自定义信息、JWT默认信息等
- Signature（签名），防止Token被篡改、确保安全性，讲header、payload融入，**==并加入指定密钥，通过指定签名算法计算而来==**

>JWT的长度不是固定的，由Header、Payload携带的数据决定
>
>Base64编码： 一种基于64个可打印字符来表示二进制数据的编码方式 
>JWT三个部分都会通过编码

JJWT：是Java实现JWT操作的工具库
作用：
- 生成JWT令牌
- 解析JWT令牌

JWT解析异常可能失败原因：
- Token被修改了
- Token超过有效时间
- Token格式错误

>JWT解析失败本质是解析过程中发生异常，  
  JJWT框架会将不同失败情况封装成异常对象并抛出
>注意：令牌生成时的指定的密钥必须和解析时的密钥相同

# 4.Java实现JWT令牌的生成和解析

## 4.1生成JWT令牌
作用：根据用户信息生成用户凭证
```java
String jwt = Jwts.builder()
        .signWith(SignatureAlgorithm.HS256, SECRET_KEY)
        .addClaims(claims)
        .setExpiration(
            new Date(System.currentTimeMillis()+EXPIRE_TIME)
        )
        .compact();
}
```
>密钥内容自定义，然后通过base64加密得到

| 方法              | 作用        |
| --------------- | --------- |
| signWith()      | 设置签名算法和密钥 |
| addClaims()     | 添加自定义数据   |
| setExpiration() | 设置过期时间    |
| compact()       | 生成JWT     |

## 4.2解析JWT令牌
作用：验证Token合法性，并获取Payload中的数据
```java
Claims claims = Jwts.parser()
        .setSigningKey(SECRET_KEY)
        .parseClaimsJws(token)
        .getBody();
```

| 方法               | 作用          |
| ---------------- | ----------- |
| setSigningKey()  | 指定解析密钥      |
| parseClaimsJws() | 解析并验证JWT    |
| getBody()        | 获取Payload数据 |
## 4.3基于以上代码利用AI生成一个JwtUtils
```java
package com.ccy.utils;  
  
import io.jsonwebtoken.Claims;  
import io.jsonwebtoken.Jwts;  
import io.jsonwebtoken.SignatureAlgorithm;  
  
import java.util.Date;  
import java.util.Map;  
  
public class JwtUtils {  
    // 密钥（生成和解析必须保持一致）  
    private static final String SECRET_KEY = "YmxnbmJ5eWRzCg==";  
  
    // 过期时间：12小时  
    private static final Long EXPIRE_TIME = 12 * 60 * 60 * 1000L;  
  
    /**  
     * 生成JWT令牌  
     *  
     * @param claims 自定义数据  
     * @return JWT令牌  
     */  
    public static String generateJwt(Map<String, Object> claims) {  
  
        String jwt = Jwts.builder()  
                // 设置签名算法和密钥  
                .signWith(SignatureAlgorithm.HS256, SECRET_KEY)  
                // 设置自定义数据  
                .addClaims(claims)  
                // 设置过期时间  
                .setExpiration(  
                        new Date(System.currentTimeMillis() + EXPIRE_TIME)  
                )  
                // 生成令牌  
                .compact();  
  
        return jwt;  
    }  
  
  
    /**  
     * 解析JWT令牌  
     *  
     * @param token JWT令牌  
     * @return 解析后的数据  
     */  
    public static Claims parseJwt(String token) {  
        Claims claims = Jwts.parser()  
                // 指定解析密钥  
                .setSigningKey(SECRET_KEY)  
                // 解析JWT  
                .parseClaimsJws(token)  
                // 获取自定义信息  
                .getBody();  
        return claims;  
    }  
}
```


 
# 5. 过滤器 Filter（传统Java开发的三大组件之一）

概念：
>Filter是Servlet规范提供的请求过滤技术
>可以在请求进入Spring MVC之前，对请求进行统一处理
>

>过滤器可以拦截对资源的请求，完成一些通用的操作，比如：登录校验、统一编码处理、敏感字符处理等


定义Filter：定义一个类，实现 Filter接口，并实现所有方法

Filter接口提供三个核心方法：
- init：初始化方法，创建Fliter实例时调用一次
- doFilter（核心）：拦截到请求时，调用该方法，可以调用很多次
- destory：web服务器关闭时调用，只调用一次

示例：
```java
public class TokenFilter implements Filter {...}
```

配置Filter：
- @WebFilter：Filter类上加注解，配置拦截路径
	- 具体路径： "/login"
	- 所有路径："/\*"
	- 目录拦截："/emps/\*"
- @ServletComponentScan：在引导类上加注解开启SpringBoot对Servlet组件的支持

放行操作:
```java
chain.doFilter(request,response);
```

 **==令牌校验Filter-流程 (核心) ==**：

1. 请求进入Filter
2. 获取请求路径
3. 判断是否为登录接口：
   - 是：直接放行
   - 否：进入Token校验流程
4. 获取请求头中的Token：
   - Token不存在：返回401
   - Token存在：
       - JWT解析成功：放行
       - JWT解析失败：返回401

核心目的：
在请求进入Controller之前完成身份认证，
认证通过后才允许访问业务接口。

Java实现JWT令牌校验过滤器代码：
```java
package com.ccy.filter;  
  
import com.ccy.utils.JwtUtils;  
import jakarta.servlet.*;  
import jakarta.servlet.annotation.WebFilter;  
import jakarta.servlet.http.HttpServletRequest;  
import jakarta.servlet.http.HttpServletResponse;  
import lombok.extern.slf4j.Slf4j;  
  
import java.io.IOException;  
  
@Slf4j  
@WebFilter  
public class TokenFilter implements Filter{  
    @Override  
    public void init(FilterConfig filterConfig) throws ServletException {  
        Filter.super.init(filterConfig);  
    }  
  
    @Override  
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) throws IOException, ServletException {  
  
        // 获取 客户端发来的 http请求 和 服务器准备的 http响应  
        HttpServletRequest httpServletRequest = (HttpServletRequest) request;  
        HttpServletResponse httpServletResponse = (HttpServletResponse) response;  
  
        // 1.获取到请求路径  
        String requestURL = httpServletRequest.getRequestURI();  
  
        // 2.判断是否为登录请求  
        if(requestURL.contains("/login")){  
            log.info("登录请求，放行~");  
            chain.doFilter(request,response);  
            return;  
        }  
  
        // 3.获取请求头中的token  
  
        String token = httpServletRequest.getHeader("token");  
  
        // 4. 判断token是否存在，如果不存在，说明用户没有登录，返回401  
        if(token == null || token.isEmpty()){  
            log.info("令牌为空，响应401");  
            httpServletResponse.setStatus(401);  
            return;  
        }  
  
        // 5.如果token令牌存在,调用 JwtUtils 的校验方法  
        //JwtUtils.parseJwt(token);  
  
        try{  
            JwtUtils.parseJwt(token);  
        }catch (Exception e){  
            log.info("令牌非法，响应401");  
            httpServletResponse.setStatus(401);  
            return;  
        }  
  
        log.info("令牌合法，放行");  
        chain.doFilter(request,response);  
  
    }  
  
    @Override  
    public void destroy() {  
        Filter.super.destroy();  
    }  
}
```


>request（HttpServletRequest）就是服务器接收到的“客户端本次请求的所有信息的封装对象”；
>response（HttpServletResponse）就是服务器准备返回给客户端的“响应信息的封装对象”。

JWT解析为什么使用try-catch不适用if-esle？

JWT的token解析函数中：
```java
parseClaimsJws(token)
```
会出现多种失败情况：
- token被修改
- token过期
- token格式错误

本质都是解析JWT过程中给发生了异常，JWT框架统一将这些失败情况封装成异常对象
所以要用try-catch捕获异常对象

>异常是程序运行时抛出的对象，try-catch负责捕获这个异常对象并处理；控制台报错只是异常没有被捕获时，JVM默认打印出来的表现

>f-else用于处理程序正常运行中的业务分支，例如用户名密码是否正确；try-catch用于处理程序运行过程中可能发生的异常情况，例如JWT解析失败、数据库连接失败。JWT解析失败原因较多，JWT框架将不同失败情况统一封装成异常对象并抛出，因此业务层通过try-catch捕获异常并进行统一处理。

正常情况用if-else，异常情况用try-catch；不要用if-else模拟异常处理


过滤器链
- 一个web应用中，可以配置多个过滤器，形成一个过滤器链
- 注解配置的Filter，优先级是按照过滤器类名（字符串）的自然排序


# 6. 拦截器 Interceptor
Interceptor是Spring MVC提供的请求拦截技术， 用于在Controller方法执行前后执行额外逻辑

创建拦截器：实现HandlerInterceptor接口

三个核心方法：
- preHandle：在目标资源方法（Controller执行前执行）执行前执行，返回==**true：放行，返回false：不放行**==
- postHandle：目标资源方法（Controller执行后执行）执行后执行
- afterCompletion：最后执行

拦截器HandlerInterceptor是Spring当中提供的技术，让Spring创建Interceptor对象，加入IOC容器，加上注解@Component 

注册拦截器：@Configuration配置类，实现WebMvcConfigurer接口，重写addInterceptors() 告诉Spring MVC 哪些请求需要经过该Interceptor

拦截器配置

```java
@Configuration  
public class WebConfig implements WebMvcConfigurer {  
  
    @Autowired  
    private TokenInterceptor tokenInterceptor;  
    @Override  
    public void addInterceptors(InterceptorRegistry registry) {  
        registry.addInterceptor(tokenInterceptor).addPathPatterns("/**");  
    }  
}
```

>配置中可以设置拦截的资源范围：
>addPathPatterns() 添加请求路径
>excludePathPatterns() 排除请求路径

基于拦截器实现令牌校验

```java
@Slf4j  
@Component  
public class TokenInterceptor implements HandlerInterceptor {  
    @Override  
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {  
  
        // 1.获取到请求路径  
        String requestURL = request.getRequestURI();  
  
        // 2.判断是否为登录请求  
        if(requestURL.contains("/login")){  
            log.info("登录请求，放行~");  
            return true;  
        }  
  
        // 3.获取请求头中的token  
  
        String token = request.getHeader("token");  
  
        // 4. 判断token是否存在，如果不存在，说明用户没有登录，返回401  
        if(token == null || token.isEmpty()){  
            log.info("令牌为空，响应401");  
            response.setStatus(401);  
            return false;  
        }  
  
        // 5.如果token令牌存在,调用 JwtUtils 的校验方法  
        //JwtUtils.parseJwt(token);  
  
        try{  
            JwtUtils.parseJwt(token);  
        }catch (Exception e){  
            log.info("令牌非法，响应401");  
            response.setStatus(401);  
            return false;  
        }  
  
        log.info("令牌合法，放行");  
        return true;  
  
    }  
}
```

# 7.Filter & Intereptor的区别
 
> Filter是Servlet规范提供的技术，运行在DispatcherServlet之前，可以对所有进入Web服务器的请求进行过滤；
> 
> Interceptor是Spring MVC提供的技术，运行在DispatcherServlet之后、Controller执行之前，可以更加细粒度地拦截Controller请求。
> 
> Filter适合做编码处理、登录认证等全局过滤；
> 
> Interceptor适合做权限校验、操作日志等Spring MVC相关的业务处理。

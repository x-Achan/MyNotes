#### 路径参数和查询参数区别？
路径参数（PathVariable）和查询参数（RequestParam）都可以向后端传递数据，但表达的语义不同。
路径参数用于表示资源本身或资源之间的层级关系，通常用于根据唯一标识获取、修改、删除某个具体资源，例如 `GET /depts/1` 表示查询 id 为 1 的部门；
查询参数用于对资源集合进行筛选、排序、分页等操作，表示查询条件或额外信息，例如 `GET /depts?page=1&pageSize=10` 表示查询部门列表的第1页数据。
在 RESTful 风格接口设计中，资源定位使用路径参数，条件查询使用查询参数。

>==两者在技术实现上都能传递参数，甚至可以实现相同功能，但路径参数强调资源的唯一性和层级关系，查询参数强调对资源集合的过滤和控制，是 REST API 设计中的语义区分。==

#### 对于HTTP四种请求方式的总结

>HTTP方法本身不会限制服务器必须执行什么操作，GET、POST、PUT、DELETE在技术上都可以执行任意业务逻辑。
>
>但是为了符合RESTful接口设计规范，需要按照HTTP方法语义使用：
>GET表示查询资源，POST表示创建资源，PUT表示修改资源，DELETE表示删除资源。
>
>这样可以提高接口可读性，并保证与浏览器、缓存、代理等HTTP生态组件正常协作。


#### 原始分页查询

方法：两条SQL语句实现：
- 查询结果列表
- 统计总记录数
- 
前端需要传递给后端的参数（通过GET接收参数）
- page：当前页码
- pageSize：每页展示的记录数

后端需要给前端的返回结果
-  rows（指定页码对应的数据列表）：服务器端Service层根据页码page和每页记录数pageSize，计算起始索引start，Mapper层再去执行分页查询的SQL语句，获取到指定页码的数据列表（limit）
```java
// 起始索引计算方法
start = (page - 1) * pageSize;
```

- total：总记录数 （count）

```java
// 分页查询SQL语句
@Select("select e.*,d.name deptName from emp e left join dept d on e.dept_id = d.id limit #{start},#{pageSize}")  
public List<Emp> list(Integer start,Integer pageSize);

// 计算总记录数
@Select("select count(*) from emp e left join dept d on e.dept_id = d.id")  
public Long count();
```

#### PageHelper（Mybatis提供的插件）分页查询

1. 依赖
```xml

<dependency>  
    <groupId>com.github.pagehelper</groupId>  
    <artifactId>pagehelper-spring-boot-starter</artifactId>  
    <version>1.4.7</version>  
</dependency>
```

  2. 定义Mapper中的接口查询方法（无需考虑分页）
```java
@Select("select e.*,d.name deptName from emp e left join dept d on e.dept_id = d.id")  
public List<Emp> list();
```

3. 在Service方法中实现分页查询
```java
    @Override  
    public PageResult<Emp> page(Integer page,Integer pageSize){  
        // 1.设置分页参数  
        PageHelper.startPage(page,pageSize);  
  
        // 2.执行查询  
        List<Emp> empList = empMapper.list();  
  
        // 3.解析查询结果，并封装  
        Page<Emp> p = (Page<Emp>) empList;  
        return new PageResult<Emp>(p.getTotal(),p.getResult());  
    }  
}
```

解析：
PageHelper采用的时无侵入分页，业务代码不需要关注分页，自动完成

第一步设置完分页条件page和pageSize，在第2步执行empMapper.list()时，MyBatis执行SQL，PageHelper会拦截
原SQL:

```sql
select * from emp
```
变成：
```sql
select count(*) from emp

select * from emp limit 10,10
```
返回：
```java
Page<Emp>
{

total=100,

result=[
员工11,
员工12,
...
员工20
]

}
```

因此可以通过p.getTotal()和p.getResult()得到
- 总数量
- 当页数据

Page数据结构extends了ArrayList，所以可以List可以强转为Page

4. 注意事项
- SQL语句结尾不要加分号(;)
- PageHelper只会对紧跟在其后的第一条SQL语句进行分页处理

#### 请求参数接收优化方案

queryString查询参数接收方式中：
如果Controller接收参数过多，且未来可能增加
用一个实体类包装所有参数
在请求方法中传入实体类
会自动获取对象中的属性名，得到参数

>Spring MVC 支持将请求参数自动封装到实体类对象中，实体类中的属性会根据请求参数名自动匹配赋值。即使业务方法只需要其中部分属性，也可以传入完整实体对象，未使用的属性不会影响程序执行。这种方式可以减少 Controller 方法参数数量，提高代码可维护性。

1. 定义一个参数实体类
```java
@Data

    private Integer page = 1;  
    private Integer pageSize = 10;  
    private String name;  
    private Integer gender;  
    @DateTimeFormat(pattern = "yyyy-MM-dd")  
    private LocalDate begin;  
    @DateTimeFormat(pattern = "yyyy-MM-dd")  
    private LocalDate end;  
}
```
2. 原方法
```java
@GetMapping  
public Result page(@RequestParam(defaultValue = "1") Integer page,  
                   @RequestParam(defaultValue = "10")Integer pageSize,  
                   String name,  
                   Integer gender,  
                   @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate begin,  
                   @DateTimeFormat(pattern = "yyyy-MM-dd")LocalDate end)
                   
                   
```

3. 新方法
```java
public Result page(EmpQueryParam empQueryParam){  
    log.info("分页请求参数：{},{},{},{},{},{}",empQueryParam);  
    PageResult<Emp> pageResult = empService.page(empQueryParam);  
    return Result.success(pageResult);

```

service 和 mapper 接口中的方法都可以传入一个实体类，替换掉之前的多参数
在mapper.xml文件也会自动识别，所以不用修改

#### 动态SQL

- foreach 循环SQL语句
再插入insert员工工作经历的时候，工作经历的数量是动态变化的，所有inset后的values内容数量不一定，用foreach字段设置循环

```java
<mapper namespace="com.ccy.mapper.EmpExprMapper">  
    <insert id="insertBatch">  
        insert into emp_expr(emp.id,begin,end,company,job) values  
        <foreach collection="exprList" item="expr" separator=",">  
            (#{expr.empId},#{expr.begin},#{expr.end},#{expr.company},#{expr.job})  
        </foreach>>  
    </insert>  
      
</mapper>
```

作用：遍历集合/数组
属性：
- collection：集合名称
- item：集合遍历出来的元素/项
- sqparator：每一次遍历使用的分隔符（可选）
- open：遍历开始前拼接的片段（可选）
- close：遍历结束后拼接的片段（可选）

Mybatis中封装查询结果，什么时候用 resultType，什么时候用resultMap?

```json
  "pos":"学工主管",
  "num":5

```

```json
List<Map<String,Object>> list
```

>这种封装方式适合返回给图标

```java
List<Object> jobList =
    list.stream()
        .map(dataMap -> dataMap.get("pos"))

```

stream()会将集合中的元素转为流
stream().map(...)对流中每一个元素进行处理
dataMap -> dataMap.get("pos")将原本的map都进行替换
toList()把stream流重新收集成List

xml配置：
```xml
<select id="countEmpJobData" resultType="java.util.Map">

```

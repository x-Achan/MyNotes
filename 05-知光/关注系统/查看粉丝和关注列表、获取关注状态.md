
# 一、读取粉丝/关注用户id列表

## 1. 流程

第一次查看第一页：

```
Redis 没有 ZSet
    ↓
MySQL LIMIT 30 OFFSET 0
    ↓
写入 __INIT__
    ↓
写入 30 个用户 ID
```

继续查看第二页：

```
Redis 已有 30 条
    ↓
MySQL LIMIT 30 OFFSET 30
    ↓
追加到 ZSet
```

继续查看第三页：

```
Redis 已有 60 条
    ↓
MySQL LIMIT 30 OFFSET 60
    ↓
追加到 ZSet
```

关注或取关：

```
删除对应关注列表 ZSet
删除对应粉丝列表 ZSet
刷新 Redis 计数
```

下一次查看：

```
ZSet 不存在
    ↓
从 MySQL 重新加载前 30 条
```


```
读取列表
    ↓
Redis ZSet 是否存在？
    ├── 不存在：加锁
    │       ↓
    │   双重检查
    │       ↓
    │   MySQL LIMIT 30 OFFSET 0
    │       ↓
    │   写入 ZSet
    │
    └── 存在：
            ↓
        缓存数据是否满足当前页？
            ├── 是：Redis 分页读取
            └── 否：加锁
                    ↓
                双重检查
                    ↓
                MySQL LIMIT 30 OFFSET cachedCount
                    ↓
                追加到 ZSet
                    ↓
                Redis 分页读取
```

## 2. 核心代码


第一步：读取时先读取ZSet缓存，有三种情况
- 缓存没有数据
- 缓存 1-30条，用户请求 1- 30条
- 缓存 1-30 条，用户请求 30 -60条

如果缓存没有数据，或者用户请求超出范围

从ZSet分页读取，ZSet是有序的，支持分页读取，传入key，start，end，将元素装入String集合
```java
Set<String> members = redis.opsForZSet().reverseRange(key, start, end);
```

第二步：缓存未命中，需要获取锁，完成重建（防止缓存击穿，使用分布式锁）
先获取锁
```java
RLock lock = redisson.getLock(lockKey);
boolean locked = lock.tryLock(2, 15, TimeUnit.SECONDS);
```
获取锁成功后，要双重检查，也就是再执行一次第一步的工作，查询Redis缓存
获取成功，直接读取
获取失败进入核心阶段：追加MySQL分页数据，重建缓存

第三步：获取数据库
分页查询SQL
```xml
<select id="listFollowingRows" resultType="map">  
    SELECT to_user_id AS userId, created_at AS createdAt    
    FROM following    
    WHERE from_user_id = #{fromUserId}      
    AND rel_status = 1    
    ORDER BY created_at DESC, to_user_id DESC    
    LIMIT #{limit} OFFSET #{offset}
    </select>
```

获取到用户Id列表，然后保存到Redis中，完成重建
```java
redis.opsForZSet().add(zsetKey, tuples);
```


## 3.ZSet首位标记设计 

 __INIT__：区分缓存未初始化和空列表

Redis 中的 ZSet 如果最后一个元素被删除，整个 Key 会消失

所以这两种情况无法直接区分：

```
Key 不存在：
说明缓存还没有建立
```

```
Key 存在但没有用户：
说明缓存已经建立，只是数据库中没有关注关系
```

因此保存一个头部记录：

```
rel:following:1001
    __INIT__   +Infinity
```

表示：

```
这个用户的关注列表已经加载过，当前确实为空
```

如果没有 `__INIT__`，下一次查询会认为缓存未初始化，从数据库重复重建。

__END__：表示已经加载到列表末尾

假设每次只加载 30 条：

```
第一次加载：1～30
第二次加载：31～60
```

当某次查询数据库返回数量小于 30 时，说明数据库已经没有更多数据。

例如：

```
当前查询 OFFSET 60 LIMIT 30
实际只返回 12 条
```

说明总共只有 72 条数据。

此时加入：

```
__END__   -Infinity
```

下次用户继续向下滑时，就知道已经到底，不需要继续访问数据库

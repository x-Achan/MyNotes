# 一、关注
## 1.总流程

```
① A 点"关注"
    ↓
② 令牌桶检查（rl:follow:A）
    → 通过
    ↓
③ 事务：
    INSERT following (from=A, to=B, status=1)
    INSERT outbox (aggregate_type='following', event_id=UUID, payload=JSON)
    ↓
④ 提交
    ↓
⑤ 异步 relay（每 500ms）：
    读 outbox → 发 Kafka → 更新游标
    ↓
⑥ Kafka 消费者：
    幂等检查（dedup:rel:{eventId}）
    INCR ucnt:A:followings
    INCR ucnt:B:followers
    ZADD uf:flws:A {ts} B
    ZADD uf:fans:B {ts} A
    ↓
⑦ ack
```

## 三、补充介绍

### 1. 关注插入数据库分情况原因

因为删除时是逻辑删除，所以新关注的一条插入，需要判断这是否是第一次插入，每次插入的时间都不同，所以如果用ON DUPLICATE KEY UPDATE，拦截不住，所以要拆分成两个语句
- 首先尝试尝试插入 insert
- 如果没有成功，说明记录存在，是逻辑删除，更新语句 update
>follow表中的 status 标识当前的关注状态（是否有效）,使用status是为了以后可以扩展 拉黑 屏蔽 等其他状态

关注，插入语句sql，只在真的插入时返回 1
```xml
<insert id="insertFollowingIfAbsent">  
    INSERT IGNORE INTO following (id, from_user_id, to_user_id, rel_status, created_at, updated_at)    
    VALUES (#{id}, #{fromUserId}, #{toUserId}, 1, NOW(3), NOW(3))
</insert>
```
更新语句，修改状态，重新关注

```xml
<update id="reviveFollowing">  
    UPDATE following    
    SET rel_status = 1, updated_at = NOW(3)    
    WHERE from_user_id = #{fromUserId}      
    AND to_user_id = #{toUserId}      
    AND rel_status = 0
</update>
```

### 3. Redis中主要存储

- 幂等键：收到重复消息保证幂等
- 计数键：每个用户的关注数，粉丝数
- 列表键Zset：每个用户的关注列表，粉丝列表

```
// 幂等键
dedup:rel:{eventId}

// 计数键（两个）
ucnt:{userId}:{metric}

// Zset
uf:flws:{userId}
uf:fans:{userId
```


### 4. Lua脚本

1. 更新计数键

```lua
if redis.call('EXISTS', KEYS[1]) == 1 then  
    return 0
end  

if redis.call('EXISTS', KEYS[2]) == 0 or redis.call('EXISTS', KEYS[3]) == 0 then  
    return -1
end  

redis.call('SET', KEYS[1], '1', 'EX', ARGV[2])  
local d = tonumber(ARGV[1])  

if d ~= 0 then  
    redis.call('INCRBY', KEYS[2], d)    redis.call('INCRBY', KEYS[3], d)
end  

return 1
```

如果幂等键获取失败，直接返回0，说明是重复消息
如果计数key获取失败，reids未命中，返回 -1，需要查数据库计数，重建redis
获取幂等键，对两个计数Key，执行自增操作INCE，返回 1
这三个操作包含查询和自增，使用lua脚本保证原子性

2. 更新ZSet键
```lua
if redis.call('EXISTS', KEYS[1]) == 0 then  
    return 0
end  
redis.call('ZADD', KEYS[1], ARGV[2], ARGV[1])  
redis.call('EXPIRE', KEYS[1], ARGV[3])  
return 1
```

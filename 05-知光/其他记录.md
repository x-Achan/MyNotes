**核心结论**：这是**社交系统中"关注关系"的经典设计** —— **同一份数据，存两次（正反双向）**，来**加速双向查询**。

# Optional

`Optional<T>` 是 **Java 8** 引入的一个**容器类**，用来**显式地表示"一个值可能存在，也可能不存在"**。
它本质上就是**对 null 的一层包装**，强制调用方**主动处理"可能没有值"的情况**，而不是忘记判空导致 `NullPointerException`。

`Optional.ofNullable(x)` 的作用：
- `x != null` → 返回 `Optional.of(x)`
- `x == null` → 返回 `Optional.empty()`

**它是给方法返回值用的**，别拿它当字段、当参数、当集合替代品。


```
Mapper
    ↓
User / null

Service
    ↓
Optional<User>

业务层
    ↓
显式处理“用户不存在”
```





# DTO设计

## 方式1：Java Record设计 LoginRequest
```java
/**  
 * 登录请求。  
 * <p>  
 * 支持两种渠道：  
 * - 验证码登录：填写 `code`；  
 * - 密码登录：填写 `password`（用户已设置时）。  
 * `identifierType` 指定账号类型（手机号/邮箱），`identifier` 为账号值。  
 */  
public record LoginRequest(  
        @NotNull(message = "账号类型不能为空")  
        IdentifierType identifierType,  
        @NotBlank(message = "账号不能为空")  
        String identifier,  
        // code 和 password 二选一  
        String code,  
        String password  
) {  
}
```

这段代码用 **Java Record** 定义了一个**不可变的登录请求 DTO**，包含 4 个字段：账号类型、账号、验证码、密码。  
**`@NotNull` / `@NotBlank`** 负责在进入 Controller 前**自动校验必填项**，`message` 指定友好的错误提示。  
`code` 和 `password` 故意不校验，是为了支持**验证码登录 / 密码登录二选一**，需要在 Service 层补充业务判断。  
整体设计简洁、语义清晰，是 Spring Boot 3 + Java 21 的**推荐写法**。

## 方式2：传统方法`@Data` + 无参/全参构造

```java
package com.zhiguang.auth.api.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import com.zhiguang.auth.model.IdentifierType;
import lombok.Data;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;

@Data
@NoArgsConstructor
@AllArgsConstructor
public class LoginRequest {

    @NotNull(message = "账号类型不能为空")
    private IdentifierType identifierType;

    @NotBlank(message = "账号不能为空")
    private String identifier;

    private String code;

    private String password;
}
```

关键区别：访问器命名不同
```java
// record
req.identifierType()

// class
req.getIdentifierType()
```


# Spring 补充

## Service 里的依赖要定义为 `final`

```java
@Service  
@RequiredArgsConstructor  
public class AuthService {  
  
    private final UserService userService;  
    private final PasswordEncoder passwordEncoder;
    ...
    ...
    
}
```

`final` 的含义是：**这个引用一旦被赋值，就再也不能指向别的对象**

**核心结论**：`final` 不只是"语法习惯"，它带来的是**不可变性、线程安全、编译期保障、构造器注入的必然要求**。这是 Spring 官方推荐的**构造器注入**写法的关键部分。

`@RequiredArgsConstructor` 只认 `final` / `@NonNull`

## Mapper 是怎么变成 Bean 的

**MyBatis-Spring 在启动时扫描所有 Mapper 接口，为每个接口动态生成一个代理对象（JDK 动态代理），注册到 Spring 容器**

所以 Mapper 可以被构造器注入、被其他 Bean 依赖，就像普通 Bean 一样
**扫描方式二选一**：
- 每个接口加 `@Mapper`
- 启动类加 `@MapperScan("com.xxx.mapper")`


**`Resource` 是 Spring 的抽象**，能自动加载**各种来源**
```
private Resource privateKey; //私钥  
private Resource publicKey; //公钥
```


## `AuthProperties` 的设计思想讲解

> JWT私钥信息不能保存在类中，上传Git别人会看到密钥，所以写入yaml配置文件，再映射到一个类中

采用 **Spring Boot 的"类型安全配置绑定"（Type-Safe Configuration Properties）** 设计，配合**嵌套配置**和**内聚的配置对象**模式。它把散落在 `application.yml` 里的配置，**绑定成一个强类型的 Java 对象**，让配置**可读、可校验、可复用**。

传统方法@Value

```java
// ❌ 传统方式：散落、弱类型、难维护
@Value("${auth.jwt.secret}")
private String secret
```

**`@ConfigurationProperties` 方式**：

```java
@ConfigurationProperties(prefix = "auth")
public class AuthProperties {
    private Jwt jwt = new Jwt();
    // ...
}
```

Duration自动转换时间：30m -> Duration.ofMinutes(30)

```java
private Duration accessTokenTtl;
```

对应

```yml
access-token-ttl: 30m
```

JW密钥存放在application.yml中

```yaml
auth:
  jwt:
    secret: zhiguang-secret-key-please-change-in-production
    access-token-ttl: 30m
    refresh-token-ttl: 7d
    issuer: zhiguang
```

@ConfigurationProperties 把配置文件映射成 Java 对象  
配置：

```
auth:
  jwt:
    issuer: zhiguang
```

自动变成：

```
properties.getJwt().getIssuer()
```

这就是AuthProperties存在的意义



# `ObjectMapper` 是什么？

**核心结论**：`ObjectMapper` 是 **Jackson 库**里最核心的类，用来做 **Java 对象 ↔ JSON 字符串的互相转换**。

**一句话**：**Java 世界的"JSON 翻译官"** —— 你给它 Java 对象，它吐出 JSON；你给它 JSON，它变回 Java 对象。

---

## 一、它是谁？

**来自**：

java

import com.fasterxml.jackson.databind.ObjectMapper;

**所属库**：**Jackson**（Spring Boot 默认的 JSON 库）。

**作用**：

| 操作                 | 方法                               |
| ------------------ | -------------------------------- |
| **Java 对象 → JSON** | `writeValueAsString(obj)`        |
| **JSON → Java 对象** | `readValue(json, Class)`         |
| **JSON → 复杂泛型**    | `readValue(json, TypeReference)` |
| **JSON ↔ Map**     | 自动                               |
| **JSON ↔ Tree**    | `readTree(json)`                 |



**`ObjectMapper.writeValueAsString()` 是"受检异常"（Checked Exception）** —— **Java 编译器强制你处理**，不处理就编译不过
### 方式 1：**`try-catch`**（推荐）

### 方式 2：**往上抛（`throws`）**
### 方式 3：**包装成 `RuntimeException`**（工具方法）

包装成工具类：在工具类中try-catch 进行异常处理：
```java
private String toJsonOrNull(List<String> list) {  
    if (list == null) {  
        return null;  
    }  
    try {  
        return objectMapper.writeValueAsString(list);  
    } catch (JsonProcessingException e) {  
        throw new BusinessException(ErrorCode.BAD_REQUEST, "JSON 处理失败");  
    }  
}
```

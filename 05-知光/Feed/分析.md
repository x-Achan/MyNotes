# 三级缓存

Redis结构
```
# 排序索引
feed:author:{authorId}                 保存作者全部未删除帖子
feed:hot:public:{rankingVersion}       热门帖子
feed:inbox:{userId}                    普通作者推送收件箱
feed:following:pull:{userId}           当前用户关注的大V

# 页面缓存
feed:page:hot:{version}:{cursorHash}:{size}
feed:page:profile:{authorId}:{scope}:{cursorHash}:{size}
feed:page:following:{userId}:{cursorHash}:{size}

# 帖子分片
feed:item:{postId}

# 计数，复用现有设计
cnt:knowpost:{postId}:like
cnt:knowpost:{postId}:fav
```


#### L1：Caffeine本地缓存

只保存热点页面ID + 热点分片
- 热门 Feed 第一页
- 关注 Feed 第一页
- 大 V 主页第一页

#### ZSet排序索引缓存

排序规则如下
作者Feed：postId + 创建时间
热门Feed：postId + 热门值
关注Feed：关注的大V的帖子（pull） + 关注的普通作者（push）

```
页面需要20篇
→ 从ZSet读取40个候选
→ MGET帖子分片
→ 根据status和visible过滤
→ 如果不足20篇，继续读取下一批
```

当作者创建草稿的时候，ZSet添加草稿
修改标题、正文、可见性时，仅删除帖子分片，不用调整ZSet，因为postId和创建时间没有变
发布帖子的时候，修改published，更新帖子分片，根据可见性，计算hotscore决定是否进入热门Feed和关注Feed
删除帖子分片，删除帖子分片

当一篇帖子点赞/收藏高频变化时，合并MGET点赞数和收藏数，重新计算hotScore，ZADD覆盖旧score


#### L2：页面缓存，也要分为作者/热门/关注Feed

每一个页面缓存key，对应ZSet里一页的20个postId
每一页的Key，由该页的cursor算出

用户每次请求携带cursor，请求一页（20个Id），每一页都有自己的cursorHash，用户用cursor计算cursorHash，然后请求页面缓存，如果未命中，再用cursorHash从ZSet中获取

页面缓存从ZSet重建，每次获取40个id，筛选条件过滤，得到20个

保存固定数量的 postId 和 游标nextCursor，用String保存json

```java
{
  "postIds": ["101", "203", "305", "407", ...],
  "nextCursor": "eyJ0aW1lIjoxNzYwMzIwODAwMTIzLCJpZCI6IjkwMDEifQ",
  "hasMore": true
}
```


#### L3：分片缓存
每一个帖子一个key，保存帖子的稳定信息，变化频繁的信息不保存，避免频繁删除，当其中的稳定信息更新时，比如帖子改标题，就直接让分片缓存失效，懒重建（等到下次读的时候再重建）





```
┌─────────────────────────────────────────────────┐
│  用户请求 Feed                                    │
└─────────────┬───────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────┐
│  L1 Caffeine（本地）                              │
│  缓存"热点页面 ID + 热点分片"                       │
│  TTL: 5~15 秒                                    │
└─────────────┬───────────────────────────────────┘
              ↓ 未命中
┌─────────────────────────────────────────────────┐
│  L2 Redis 页面缓存（String + JSON）                │
│  key: feed:page:hot:v1:hash:20                   │
│  value: { postIds, nextCursor, hasMore }         │
│  TTL: 30~120 秒                                  │
└─────────────┬───────────────────────────────────┘
              ↓ 未命中
┌─────────────────────────────────────────────────┐
│  ZSet（排序索引）                                  │
│  key: feed:hot:public                            │
│  member: postId, score: hotScore                 │
│  → 取"排序好的 ID 列表"                            │
└─────────────┬───────────────────────────────────┘
              ↓ 拿到 ID
┌─────────────────────────────────────────────────┐
│  L3 Redis 分片缓存（String + JSON）                │
│  key: feed:item:{postId}                         │
│  value: { title, description, coverImage(url),   │
│           contentUrl(url), imgUrls(urls), ... }  │
│  TTL: 10~30 分钟                                 │
└─────────────┬───────────────────────────────────┘
              ↓ 缺失
┌─────────────────────────────────────────────────┐
│  MySQL（真相源）                                  │
│  → 重建分片缓存                                   │
└─────────────┬───────────────────────────────────┘
              ↓ 补充
┌─────────────────────────────────────────────────┐
│  计数 / 用户状态                                  │
│  MGET cnt:knowpost:{id}:like                     │
│  MGET cnt:knowpost:{id}:fav                      │
│  GETBIT 用户点赞位图                              │
└─────────────┬───────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────┐
│  组装返回：                                       │
│  { items: [...], nextCursor, hasMore }           │
│  items 里的"图片/正文"是 URL                      │
│  → 前端"拿 URL 请求 CDN"                          │
└─────────────────────────────────────────────────┘
```


滑动加载流程

```
① 用户滑到底 → 前端"发请求"（带 cursor）
    ↓
② 后端：
    - 算 cursorHash
    - 查页面缓存 key
    - 命中 → 返回 ✅
    - 未命中 → 用 cursor 查 ZSet → 拿 20 个 → 写缓存 → 返回 ✅
    ↓
③ 前端"追加"新数据到列表
```


# 五、版本号怎么维护

## 作者版本

```
feed:version:author:{authorId}
```

以下操作发生时执行 `INCR`：

- 创建草稿
- 发布帖子
- 删除帖子
- 修改标题、摘要、封面
- 修改状态
- 修改可见性

作者版本变化后：

```
v8 → v9
```

自己的主页、公开主页、粉丝主页旧缓存全部自然失效。

## 关注 Feed 用户版本

```
feed:version:following:{userId}
```

以下情况更新：

- 用户关注
- 用户取关
- 普通作者向这个用户收件箱推送帖子
- 收件箱进行了重要清理

普通作者推送时可以使用 Pipeline：

```
ZADD feed:inbox:{userId}
INCR feed:version:following:{userId}
```

## 大 V 版本

大 V 发布帖子时不能修改几百万粉丝的用户版本。

可以使用一个全局时间窗口：

```
bigVEpoch = 当前时间按1分钟或5分钟取整
```

例如：

```
202610141205
```

关注 Feed 页面 Key 包含这个窗口。

进入下一个时间窗口后，所有关注 Feed 会使用新的页面缓存 Key，旧页面等待 TTL 过期。

这样大 V 发布不产生粉丝级写扩散。

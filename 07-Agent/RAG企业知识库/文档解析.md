创建文本提取器

```java
PDFTextStripper stripper = new PDFTextStripper();
stripper.setSortByPosition(true);
```

PDFTextStripper 是 PDFBox 提取文字的核心类
setSortByPosition(true) 会尽量根据字符在页面上的坐标恢复阅读顺序

PDF 内部的文字不一定像普通文本文件那样按句子保存，不是按照阅读顺序存储文字，是按照绘制指令存储，它通常保存的是：

```
在坐标 (100, 200) 绘制“知识”
在坐标 (150, 200) 绘制“库”
```

## PDF 解析过程


```
读取 PDF
→ PDFBox 打开文档
→ 按页提取文本
→ 清理空格和换行
→ 识别页面开头的章节标题
→ 保存页码、正文和章节标题
→ 从第一页提取文档标题
→ 返回 ParseResult
```

## DOCX 解析过程

```
读取 DOCX
→ 按文档顺序遍历段落和表格
→ 根据 Heading/标题样式识别章节标题
→ 遇到新标题时保存上一节
→ 将表格转换成文本并归入当前章节
→ 保存最后一节
→ 从文档属性读取文档标题
→ 返回 ParseResult
```


## MD当前解析流程

```
读取 Markdown 文件
→ 按行遍历
→ 识别代码块范围
→ 识别一级、二级标题
→ 根据标题和长度切分章节
→ 去除 Markdown 语法
→ 每个章节构造一个 PageContent
→ 返回 ParseResult
```

## TXT
```
读取全部字节
→ 尝试 UTF-8 解码
→ 乱码较多时改用 GBK
→ 删除 BOM (隐藏字符)
→ 统一换行符
→ 检查空文本
→ 检查是否疑似二进制文件
→ 整个文件作为一个 PageContent
```


| 对比项  | DOCX          | PDF          |
| ---- | ------------- | ------------ |
| 文档性质 | 结构化编辑文档       | 固定版面展示文档     |
| 文本结构 | 有段落、表格、样式     | 主要是字符及页面坐标   |
| 标题识别 | 根据 Heading 样式 | 根据正则、字体和位置推测 |
| 阅读顺序 | 通常由 XML 顺序决定  | 需要根据坐标恢复     |
| 表格   | 有明确的行和单元格     | 通常需要检测线条和坐标  |
| 页面   | 没有稳定的逻辑页结构    | 有明确的物理页码     |
| 扫描件  | 一般不存在         | 可能需要 OCR     |
| 图片文字 | 仍需 OCR 或视觉模型  | 仍需 OCR 或视觉模型 |
| 多栏排版 | 可从结构中部分识别     | 容易发生文字顺序错乱   |
| 章节层级 | 可读取标题样式       | 通常需要推断       |

# VideoMamba-DINO 实验架构与训练全梳理

> 整理日期: 2026-05-19 | 最新实验: deformable_align_v3 (best mAP 0.7017)

---

## 一、项目概述

**方法名称**: STDA-QM (Small-object-aware Temporal Deformable Alignment with Query Mamba)

**核心思路**: 将 VideoMamba (基于 SSM 的视频骨干) 与 DINO (基于 DETR 的检测器) 结合, 通过时序可变形对齐 (Temporal Deformable Alignment) 融合多帧特征, 在中心帧上做目标检测, 特别针对交通监控场景中的小目标和遮挡问题。

**当前进度**: 第一阶段 (Feature-level Temporal Alignment) 已完成, v3 的 best mAP 突破 0.7; 第二阶段 (Query-level Temporal Mamba) 待实施。

## 三、模型架构详解

### 3.1 整体数据流

```
输入视频 [B, C, T, H, W]
    │
    ▼
┌─────────────────────────────┐
│  VideoMamba-Tiny (24层 Mamba) │  ← K400 预训练, temporal_first scan
│  输出: {5: [B*T,N,192],       │
│         11: [B*T,N,192],      │
│         17: [B*T,N,192],      │
│         23: [B*T,N,192]}      │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  MultiLayerFeatureAggregator │  ← softmax 加权: Σ(softmax(w_i) * proj_i(feat_i))
│  输出: [B*T, N, 192]         │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  Simple Feature Pyramid (SFP) │  ← ViTDet 风格: deconv↑2 + base + stride↓2 + stride↓2
│  输出: 4 层特征               │
│  level0: [B*T, 256, H/8, W/8]  │  (deconv 上采样)
│  level1: [B*T, 256, H/16, W/16] │  (基准层)
│  level2: [B*T, 256, H/32, W/32] │  (strided conv)
│  level3: [B*T, 256, H/64, W/64] │  (strided conv)
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  Input Projection            │  ← 1x1 Conv + GroupNorm → hidden_dim=256
│  + Position Encoding (Sine)  │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  Temporal Fusion (per level)  │  ← 中心帧参考 + 邻帧可变形对齐
│  [B, T, C, H, W] → [B, C, H, W]│  输出只保留中心帧
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  DINO Deformable Transformer │
│  ┌───────────────────────┐  │
│  │  Encoder (6层)         │  │  ← 可变形自注意力 + FFN
│  │  → proposals           │  │
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │  Decoder (6层)         │  │  ← 300 object queries + DN queries
│  │  → refined detections  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
    │
    ▼
  中心帧检测结果: pred_logits [B, 300, 4], pred_boxes [B, 300, 4]
```

### 3.2 VideoMamba 骨干

- **架构**: 24 层 Mamba SSM Block (非层次化, 所有层输出相同空间分辨率)
- **输入**: `[B, C, T, H, W]` → reshape 为 `[B, T*H*W, C]` → scan
- **scan_order**: `temporal_first` — 同一空间位置跨帧的 token 在内存中连续, 有利于时序建模
- **输出层**: `out_indices=[5, 11, 17, 23]`, 取第 5/11/17/23 层的隐藏状态
- **每层输出**: `[B*T, N, 192]` (N = H_p * W_p = H/16 * W/16)
- **梯度检查点**: `backbone_use_checkpoint=True, checkpoint_num=24` 全部 24 层启用, 节省显存同时增加正则化效果
- **预训练**: Kinetics-400, 8帧输入, 224 分辨率

### 3.3 MultiLayerFeatureAggregator

VideoMamba 是非层次化骨干, 4 层输出相同分辨率但不同语义深度. 聚合器学习 softmax 加权组合:

```
weights = softmax([w_0, w_1, w_2, w_3])  # 可学习参数
output = Σ(weights[i] * LayerNorm_linear_i(feat_i))
```

- 输入: `dict{5: [B*T,N,192], 11: [B*T,N,192], 17: [B*T,N,192], 23: [B*T,N,192]}`
- 输出: `[B*T, N, 192]`

### 3.4 Simple Feature Pyramid (SFP)

将单尺度特征转为 4 尺度金字塔, 遵循 ViTDet 设计:

| Level | 操作 | 分辨率 | 用途 |
|-------|------|--------|------|
| 0 | lateral_conv → ConvTranspose2d(2x) | H/8 × W/8 | 小目标检测 |
| 1 | lateral_conv (基准层) | H/16 × W/16 | 中等目标 |
| 2 | 基准 → stride=2 conv | H/32 × W/32 | 大目标 |
| 3 | level2 → stride=2 conv | H/64 × W/64 | 全局语义 |

所有层通道数统一为 `hidden_dim=256`. 使用 GroupNorm(32) 而非 BatchNorm, 适合小 batch 训练.

### 3.5 时序融合模块 (核心创新点)

所有时序融合模块在 SFP 之后、DINO encoder 之前作用, 输入 `[B, T, C, H, W]`, 输出中心帧特征 `[B, C, H, W]`.

#### 已实现的 6 种融合策略

| 模块 | 类名 | 机制 | 状态 |
|------|------|------|------|
| conv1d | `TemporalConvFusion` | depthwise 1D 时序卷积 + GroupNorm | 早期实验 |
| recalib | `TemporalRecalibFusion` | conv1d + SE-like 通道门控 | 早期实验 |
| motion_guided | `MotionGuidedTemporalFusion` | 帧差运动显著性 + 时序注意力 + 运动门控 (pre-SFP) | 已弃用 |
| deformable_align (v1) | `DeformableTemporalAlignFusion` | center-ref 可变形采样 + softmax 注意力 + 门控 | 已消融 |
| deformable_align_v2 | `SmallObjectAwareDeformableTemporalAlignFusion` | v1 + level-aware 采样 + 可靠性 + 运动门控 | 失败 |
| deformable_align_v3 | `SmallObjectAwareDeformableTemporalAlignFusionV3` | v2 修复: 扩大帧覆盖 + 简化门控 | **当前最优** |

#### deformable_align (v1) 设计

核心机制: 以中心帧为参考, 对每个邻帧学习采样偏移量, 用 `grid_sample` 采样, softmax 加权聚合.

```
center: [B, C, H, W]  (参考帧)
neighbors: [B, T, C, H, W]

1. offset_attn = Conv(cat[center_rep, neighbor - center_rep])  # 偏移 + 注意力
   → offsets: [B, T, num_points, 2, H, W]  (2D 偏移, tanh * max_offset)
   → attn_logits: [B, T, num_points, H, W]  (注意力分数)

2. grid = base_grid + normalized_offsets
   sampled = grid_sample(values, grid)  # 可变形采样

3. context = Σ(sampled * softmax(attn))  # 加权聚合

4. gate = sigmoid(Conv(cat[center, context]))
   output = GroupNorm(center + gate * context)
```

- `num_points=4`, `max_offset=4.0` (所有层统一)
- 零初始化: offset_attn 权重和偏置均为零, gate bias=-2.0 (初始接近关闭)
- 所有 T 帧都参与对齐

#### deformable_align_v2 改动 (失败)

v2 在 v1 基础上增加了三个设计:

1. **Level-aware 采样**: 高分辨率层 `num_points=4, max_offset=2.0`; 低分辨率层 `num_points=2, max_offset=3.0`
2. **可靠性估计**: `reliability_logits` 加入 attention logits, 降低错位/遮挡帧影响
3. **运动感知门控**: `update_gate` 输入 `[center; context; motion_prior]`, 三输入门控

**失败原因**:
- `temporal_radius=2` → 只有中心帧前后 2 帧 (5 帧), 帧覆盖不足
- `motion_prior` 导致双重抑制: 可靠性已经降低了错位帧的影响, motion_prior 进一步关闭门控, 导致有效梯度信号过弱

#### deformable_align_v3 修复 (当前最优)

v3 针对 v2 的失败做了 4 个改动:

| 改动 | v2 | v3 | 原因 |
|------|----|----|------|
| temporal_radius | 2 (5帧) | **3 (7帧)** | 帧覆盖不足, 靠近 v1 的全帧覆盖 |
| update_gate 输入 | [center; context; motion_prior] | **[center; context]** | 移除 motion_prior, 消除双重抑制 |
| gate bias | 高分辨率-1.0, 低分辨率-2.0 | **统一 -2.0** | 高分辨率层初始过于开放, 容易引入噪声 |
| 低分辨率 num_points | 2 | **3** | 增加大目标对齐精度 |

### 3.6 DINO 检测头

**Deformable Transformer** (6层 encoder + 6层 decoder):

- **Encoder**: 可变形自注意力 → FFN, 处理 4 尺度特征, 生成 top-K proposals
- **Decoder**: 300 object queries + DN (Denoising) queries, 6 层精炼
- **Two-stage**: `standard` 模式, encoder 输出作为初始 proposal
- **DN queries**: `dn_number=100`, `box_noise_scale=0.4`, `label_noise_ratio=0.5`
- **梯度检查点**: `enc_use_checkpoint=True, checkpoint_num=6`

**预测头**:
- 分类: `nn.Linear(256, num_classes=4)` + focal loss bias 初始化
- 回归: 3 层 MLP (256→256→4), 预测 cxcywh 格式
- 所有 6 层 decoder 都有独立的分类/回归头, 用于辅助损失

### 3.7 参数量分布

| 模块 | 估计参数量 | 占比 |
|------|-----------|------|
| VideoMamba-Tiny backbone | ~22M | ~70% |
| DINO transformer | ~8M | ~25% |
| SFP + feature_aggregator + input_proj | ~2M | ~5% |
| Temporal fusion (v3, 4 levels) | ~1.5M | ~5% |
| **总计** | **~23.7M** | 100% |

## 四、训练流程详解

### 4.1 数据集: UA-DETRAC

- **场景**: 固定交通监控摄像头, 高架道路
- **类别**: 4 类 (car/van/bus/others)
- **图像尺寸**: 配置中 resize 为 544×960
- **帧数**: 每个样本 8 帧 (num_frames=8, frame_interval=1)
- **训练集**: ~4077 clips, 4 卡 batch=4 → 每 epoch ~255 步
- **验证集**: val_sliding_step=16 (密集滑窗评估)
- **数据增强**: 随机裁剪到 img_size, ImageNet 归一化, 截断率 >0.5 的目标被过滤

### 4.2 预训练权重加载

分两阶段加载, 互不冲突:

1. **Backbone**: `videomamba_t16_k400_f8_res224.pth` (Kinetics-400 预训练)
   - pos_embed 插值适配 544×960 分辨率
   - 2D Conv → 3D Conv 的中心帧初始化

2. **DINO head**: `checkpoint0033_4scale.pth` (COCO 预训练 DINO)
   - 只加载 transformer / input_proj / class_embed / bbox_embed / label_enc
   - 跳过 backbone 和形状不匹配的权重

### 4.3 优化策略

**参数分组** (3 组不同学习率):

| 组 | 包含模块 | LR 倍率 | 实际 LR |
|----|---------|---------|---------|
| backbone | VideoMamba | 0.1 | 2e-5 |
| fpn | SFP + feature_aggregator + temporal_fusion | 1.0 | 2e-4 |
| head | DINO transformer + 预测头 | 1.0 | 2e-4 |

**关键问题**: `temporal_fusion` 归入 fpn 组, LR = 2e-4, 与已收敛的 DINO head 一样高. 但 temporal_fusion 是随机初始化的, 过高的 LR 导致前几轮快速过拟合.

**优化器**: AdamW, weight_decay=0.001

**调度器**: MultiStepLR, milestones=[12, 16], gamma=0.1

**其他**:
- 梯度累积: 2 步 (effective batch = 4×4×2 = 32)
- 梯度裁剪: clip_max_norm=0.1
- AMP 混合精度训练
- DDP 4 卡分布式训练

### 4.4 损失函数

**SetCriterion** 包含:

| 损失 | 权重 | 说明 |
|------|------|------|
| loss_ce (Focal) | 2.0 | 分类损失, alpha=0.25, gamma=2 |
| loss_bbox (L1) | 8.0 | 边界框 L1 距离 |
| loss_giou | 2.0 | Generalized IoU 损失 |
| DN loss | 同上 | Denoising query 的辅助损失 |
| Aux loss (5层) | 同上 | 5 个中间 decoder 层的辅助损失 |

**匈牙利匹配**: cost_class=2.0, cost_bbox=8.0, cost_giou=2.0

### 4.5 评估流程

- 评估指标: torchmetrics `MeanAveragePrecision`
- mAP@0.50:0.95 (主指标), mAP50, mAP75, mAP_small/medium/large
- 后处理: sigmoid → top-100 → per-class NMS (IoU=0.5) → conf_threshold=0.05
- eval_interval=2 (每 2 个 epoch 评估一次)
- Best checkpoint 按 mAP 选取

### 4.6 训练命令

```bash
# 四卡训练
torchrun --nproc_per_node=4 train.py --config configs/videomamba_dino_uadetrac_deformable_align_v3.yaml
```

### 5.4 关键发现

1. **时序融合有效**: none → v1 提升 +3.2 mAP (0.6651 → 0.6971), 证明邻帧信息对检测有显著帮助
2. **v2 失败教训**: temporal_radius 太小 + motion_prior 双重抑制, 导致 v2 低于 v1
3. **v3 成功**: 扩大帧覆盖 + 简化门控, 突破 0.7 大关
4. **mAP_small 始终偏低**: 所有方法 mAP_small < 0.34, 小目标检测仍是核心难点
5. **v1 的 best epoch=2 极端过早**: 说明 v1 的全帧对齐也带来过拟合风险

## 六、当前核心问题: 训练过拟合

### 6.1 过拟合现象

**所有实验都呈现同一模式**: best mAP 出现在训练早期, 之后大幅震荡下降.

| 配置 | best epoch | best mAP | 后续表现 |
|------|-----------|---------|---------|
| none | 12 | 0.6651 | 相对稳定, 震荡较小 |
| v1 | **2** | 0.6971 | epoch 2 后大幅下降至 0.66 附近 |
| v3 | **6** | 0.7017 | epoch 8: 0.6559, epoch 12: 0.6532, 震荡幅度 >0.05 |

### 6.2 根因分析

1. **强预训练 + 小数据集 = 快速过拟合**
   - VideoMamba (K400) + DINO (COCO) → 模型起点高
   - UA-DETRAC train ~4077 clips, 4 卡 batch=4 → 每 epoch 仅 ~255 步
   - 预训练模型只需微调即可适配, 2-6 epoch 足够收敛

2. **temporal_fusion 和主干学习速率失衡**
   - backbone lr = 2e-5, temporal_fusion lr = 2e-4 (10x)
   - temporal_fusion 是随机初始化的, lr 和已收敛的 head 一样高
   - 结果: temporal_fusion 前几轮快速过拟合, backbone 几乎不动

3. **LR 衰减策略不匹配**
   - MultiStepLR 在 [12, 16] 才衰减, 但模型 epoch 2-6 就过拟合了
   - 衰减前模型已经"瞎学"了 6 个 epoch

4. **没有防止过拟合的机制**
   - 无 EMA (Exponential Moving Average)
   - 无 cosine annealing
   - 无 backbone freeze warmup

### 6.3 解决方案

#### 方案 C: 学习率分层 + 更强正则化 (零代码改动, 最快验证)

| 优化项 | 当前值 | 建议值 | 原因 |
|--------|--------|--------|------|
| fpn_lr_multiplier (含 temporal_fusion) | 1.0 | **0.1** | 随机初始化模块用低 lr 更稳定 |
| lr_drop_epochs | [12, 16] | **[4, 8]** | 匹配实际收敛位置 |
| weight_decay | 0.001 | **0.005** | 加强 L2 正则化 |
| drop_path_rate | 0.2 | **0.3** | 随机深度正则化 |
| eval_interval | 2 | **1** | 更精确捕捉 best epoch |

注意: 当前 temporal_fusion 和 SFP/feature_aggregator 共用 fpn_lr_multiplier=1.0, 需要拆分为独立参数组.

#### 方案 A: 两阶段训练 (改动最小)

```python
# 阶段 1: 冻结 backbone + encoder, 只训 temporal_fusion + head (2-3 epoch)
freeze_epochs = 2
freeze_modules = ['backbone', 'encoder']

# 阶段 2: 全局微调 (余下 epoch)
```

预期: temporal_fusion 先从随机初始化收敛到合理值, 全局微调时所有模块协调优化.

#### 方案 B: Cosine Annealing + EMA (论文正式策略)

- `CosineAnnealingLR` 替换 `MultiStepLR`, eta_min=1e-6
- `ModelEMA` (decay=0.999), 评估时用 EMA 权重
- Warmup 1 epoch

```python
class ModelEMA:
    def __init__(self, model, decay=0.999):
        self.decay = decay
        self.shadow = {k: v.clone() for k, v in model.state_dict().items()}

    def update(self, model):
        for k, v in model.state_dict().items():
            self.shadow[k] = self.decay * self.shadow[k] + (1 - self.decay) * v

    def apply(self, model):
        self.backup = {k: v.clone() for k, v in model.state_dict().items()}
        model.load_state_dict(self.shadow)

    def restore(self, model):
        model.load_state_dict(self.backup)
```

#### 推荐实施顺序

1. **先做方案 C** (只改配置, 零代码改动, 1 天验证)
2. **如果方案 C 仍过拟合, 加方案 A** (两阶段训练, 1 天代码 + 1 天验证)
3. **方案 B (EMA + Cosine) 作为论文最终训练策略** (1 天代码 + 1 天验证)

三个方案可以叠加使用, 推荐 A+C 组合或 B+C 组合.

#### 验证标准

- best mAP >= 0.70 (不低于当前)
- best epoch 出现在 >= 8 (更晚收敛说明过拟合减轻)
- epoch 8-18 的 mAP 震荡幅度 < 0.03 (比当前的 0.05 更稳定)

## 七、时序融合未来优化方向

### 7.1 第二阶段: Query-level Temporal Mamba

**核心思路**: DINO 的 object query 是目标级表示, 跨帧传播 query 比跨帧融合 feature 更贴合目标检测.

```
DINO encoder proposals (per frame)
  → per-query Mamba SSM along temporal axis
  → center-frame query enhancement
  → DINO decoder
```

**关键设计决策**:

1. **输入选择**: encoder output (top-K proposals) 还是 decoder output (refined queries)?
   - 建议: encoder proposals, decoder 已经过单帧精炼, 时序传播收益可能更低
2. **Mamba 方向**: 每个目标位置沿时间轴做 SSM 更新
   - 输入: `[num_proposals, T, hidden_dim]`
   - 输出: `[num_proposals, hidden_dim]` (中心帧增强 query)
3. **与 DINO 集成**:
   - 在 encoder-decoder 之间插入, 作为额外的 query enhancement
   - 或替换部分 decoder 层的 self-attention 为 temporal SSM

**训练配置建议**:

```yaml
model:
  temporal_fusion: deformable_align_v3
  query_temporal_mamba: True
  mamba_d_model: 256
  mamba_n_layer: 2
  mamba_proposal_topk: 50

training:
  epochs: 12
  lr_drop_epochs: [6, 10]
  weight_decay: 0.002
  drop_path_rate: 0.3
  gradient_accumulation_steps: 2

evaluation:
  eval_interval: 1
  conf_threshold: 0.05
```

**预期收益**: 保守 +0.5-1.0 mAP, 理想 +1.5-2.0 mAP (特别是 mAP_small 和遮挡场景)

**论文叙事**: Feature-level temporal alignment recovers missing spatial evidence, while query-level state-space propagation models object persistence across frames.

### 7.2 第三阶段: Temporal Denoising Query

DINO 已有 denoising query. 可以把邻帧 GT 或邻帧高置信预测经过 motion offset 映射到中心帧附近, 作为 temporal denoising query:

```
neighbor boxes + estimated motion offset → noisy temporal queries → DINO decoder
```

这个设计与 DINO 框架贴合, 适合作为论文第二创新点.

### 7.3 其他优化方向

1. **v3 的可靠性估计改进**: 当前 reliability 直接加入 attn_logits, 可以尝试作为独立的 attention mask (hard gating)
2. **多尺度 temporal radius**: 不同层使用不同 temporal_radius, 高分辨率层用更长窗口
3. **光流引导初始化**: 用 RAFT 等光流估计初始化 deformable offsets, 加速收敛
4. **时序一致性损失**: 添加相邻帧检测结果的时序一致性约束, 减少闪烁

### 7.4 必做消融 (第二阶段)

| 实验 | 配置 | 目的 |
|------|------|------|
| v3 baseline (训练优化) | v3 + 优化训练配置 | 验证训练优化后 mAP 是否稳定 |
| + Query Temporal Mamba (encoder proposals) | v3 + query_mamba | 验证 query 级时序传播收益 |
| + Query Temporal Mamba (decoder queries) | v3 + query_mamba_dec | 对比输入来源 |
| + Query Temporal Mamba (不同 top-K) | v3 + query_mamba topk=[30,50,100] | 敏感性分析 |
